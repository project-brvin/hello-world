# Hello World AI — Cloudflare Worker

A minimal glassy chat interface served by a Cloudflare Worker. Chat responses are generated by Groq's hosted **OpenAI GPT-OSS 20B** model through a server-side API endpoint.

## Model and free-tier setup

The initial provider is Groq. The model ID is `openai/gpt-oss-20b`. Groq offers a free developer tier subject to provider rate limits; free-tier capacity and model availability can change. Requests are not billed on the free tier, but the API can return HTTP 429 when a limit is reached. Check the current [Groq rate limits](https://console.groq.com/docs/rate-limits) and [supported models](https://console.groq.com/docs/models) before increasing usage.

1. Create a Groq account and generate an API key at [Groq API Keys](https://console.groq.com/keys).
2. Add the key to the **Cloudflare Worker secret store** for the `hello-world` Worker. From this repository, run `npx wrangler@4.158.0 secret put GROQ_API_KEY` and paste the key into the hidden prompt. Alternatively, use Cloudflare Dashboard → Workers & Pages → `hello-world` → Settings → Variables and Secrets → Add → Secret, with the name `GROQ_API_KEY`.
3. Do not put the key in source code, `wrangler.jsonc`, browser JavaScript, GitHub commits, issues, or chat messages. It does not need to be a GitHub Actions secret: only the deployed Worker needs it.
4. After the secret is stored, open `https://hello-world.projectbrvin.workers.dev/api/status`. A configured service reports `"ready": true`. The homepage also displays the model connection state.

The key is not configured by this change. Until you add it, the site will clearly show that the model is not ready and chat requests will fail closed with HTTP 503.

## Local development

Use Node.js 22 or later:

```bash
npm install
```

For local model requests, create an untracked `.dev.vars` file containing:

```dotenv
GROQ_API_KEY=your-groq-key
```

Then run:

```bash
npx wrangler@4.158.0 dev
```

Never commit `.dev.vars`. The repository ignores it and common environment-file names.

## API

- `GET /api/status` reports the provider, model, and whether the server-side secret and rate-limit binding are configured. It never returns the secret.
- `POST /api/chat` accepts recent `user` / `assistant` messages as JSON and returns `{ "reply": "..." }`.
- `GET /health` returns the deployed Worker version.

The chat route is same-origin only when an Origin header is present, limits request size and message history, uses a Cloudflare per-IP rate limiter (10 requests per 60 seconds, per Cloudflare location), caps model output, and disables caching. Logs contain operational metadata only; message bodies and credentials are not logged. Provider rate limits still apply independently.

## Reproducible CI and deploy

```bash
npm ci
npm test
npm run check
npm run deploy
```

Required GitHub Actions repository secrets for deployment:

- `CLOUDFLARE_API_TOKEN`: Cloudflare API token with the minimum Workers Scripts edit permission required by the deploy workflow.
- `CLOUDFLARE_ACCOUNT_ID`: Cloudflare account ID.

The workflow validates pull requests and deploys only validated pushes to `main`. A production deployment is followed by live checks of `/health` and the homepage.
